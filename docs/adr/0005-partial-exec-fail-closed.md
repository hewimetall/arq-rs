# ADR 0005. Частичный EXEC останавливает изменения

## Статус

Принято (2026-11-23).

## Контекст

`MULTI` / `EXEC` не откатывает уже выполненные команды. Ответ `EXEC` может содержать смесь успехов и ошибок команд. Receipt, записанный в том же `EXEC`, тогда подтверждает факт записи receipt, а не согласованность индексов.

## Решение

До `MULTI` backend проверяет типы ключей и аргументы. После `EXEC` он проверяет каждый элемент ответа.

- Конфликт `WATCH`: цикл чтения повторяется в пределах лимита.
- `EXECABORT`: ни одна команда транзакции не применена, цикл начинается заново.
- Ошибка отдельной команды или набор ответов, который не совпадает с планом: результат `StorageInconsistency`.

При `StorageInconsistency` процесс прекращает изменяющие операции этой очереди, прекращает новые claim и останавливает активные child по правилу неподтверждённого lease. Автоматический ремонт индексов, снятие uniq и продолжение операции не выполняются. Read-only admin ремонт не делает.

Receipt считается доказательством успеха только вместе с постусловиями операции. Противоречие receipt и постусловий — тоже `StorageInconsistency`.

## Последствия

Гарантия согласованного перехода действует при ожидаемых типах ключей, отсутствии постороннего писателя и полном успехе команд `EXEC`. Возобновление очереди — ручная процедура из `docs/operations.md`.
