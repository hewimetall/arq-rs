# ADR 0004. Момент вызова on_dead

## Статус

Принято (2026-11-23).

## Контекст

Текст «ошибка `on_dead` не отменяет уже зафиксированный переход в DLQ» читается как вызов hook после commit. В `dispatch.py` донора порядок другой: решение dead, затем `on_dead`, затем выход из `around_dispatch`, и только после этого Rust видит outcome. Внешний middleware может заменить `dead` на `retry` после того, как hook уже выполнен.

## Решение

`on_dead` сохраняет точку вызова simple-q. Hook сообщает о Python-side dead decision и не подтверждает запись DLQ. Ошибка hook логируется и не подменяет словарь, который `dispatch` возвращает. Отдельный post-commit hook в этот контракт не входит.

`note_dead` остаётся входом bridge для исходов, которые `dispatch` не производил: claim уже перевёл задачу в DLQ по `max_deliveries` или сообщение отвергнуто до handler. Этот вызов best-effort, выполняется после транспортного commit и тоже не откатывает DLQ.

## Последствия

Наблюдатель, которому нужен факт записи в Redis, читает состояние задачи или DLQ. Факт вызова `on_dead` таким фактом не является. Hard kill может пропустить и hook, и `finally`.
