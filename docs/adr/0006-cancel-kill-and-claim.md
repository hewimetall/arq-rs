# ADR 0006. Cancel и kill видны claim

## Статус

Принято (2026-11-23).

## Контекст

Принятая команда должна блокировать повторный запуск того же исполнения. Иначе после истечения lease другой worker забирает задачу, пока старый child ещё останавливается. Состояний задачи четыре: `ready`, `inflight`, `done`, `dead`. Отдельное публичное состояние команды не вводится, но признак команды обязан лежать в записи, которую claim читает под `WATCH`.

## Решение

Cancel просит кооперативную отмену. Kill просит supervisor принудительно остановить child. Автоматической эскалации cancel в kill нет.

Команда атомарно записывается в hash задачи и привязывается к текущим `cycle_id` и, для inflight, `delivery_token`. Claim в той же транзакции, где создаёт доставку, отказывает, если у текущего цикла есть блокирующая команда.

Ready-задача переходит в `dead` сразу, с причиной `cancelled` или `killed`. Inflight сохраняет команду; обычный finish этой доставки отвергается. В `dead` задача переходит после подтверждённого прекращения исполнения. Пока прекращение не доказано, новая выдача не создаётся. Отсутствие heartbeat и истечение lease сами по себе остановку не подтверждают.

Requeue разрешён только из `dead` без незавершённой остановки и начинает новый цикл. Команда старого цикла новый цикл не блокирует.

## Последствия

Терминальная причина cancel/kill наблюдаема в DLQ. Гонка с finish разрешается порядком успешных транзакций. Восстановление после рестарта supervisor описано в `docs/operations.md`: процесс, который нельзя отождествить, не получает сигнал по одному PID.
