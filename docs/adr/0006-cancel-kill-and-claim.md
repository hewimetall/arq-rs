# ADR 0006. Cancel и kill видны claim

## Статус

Принято (2026-11-23).

## Контекст

Принятая команда должна блокировать повторный запуск того же исполнения. Иначе после истечения lease другой worker забирает задачу, пока старый child ещё останавливается. Состояний задачи четыре: `ready`, `inflight`, `done`, `dead`. Отдельное публичное состояние команды не вводится, но признак команды обязан лежать в записи, которую claim читает под `WATCH`.

## Решение

Cancel просит кооперативную отмену. Kill просит supervisor принудительно остановить child. Автоматической эскалации cancel в kill нет.

Команда атомарно записывается в hash задачи и привязывается к текущим `cycle_id` и, для inflight, `delivery_token`. Claim в той же транзакции, где создаёт доставку, отказывает, если у текущего цикла есть блокирующая команда.

Ready-задача переходит в `dead` сразу, с причиной `cancelled` или `killed`. Inflight сохраняет команду; обычный finish этой доставки отвергается. Новая выдача не создаётся, пока команда висит на цикле. Отсутствие heartbeat и истечение lease сами по себе остановку не подтверждают и сканером в DLQ не превращаются.

Requeue разрешён только из `dead` с пустым `control_op` и начинает новый цикл. Команда старого цикла новый цикл не блокирует.

Пока supervisor владеет child, наблюдаемый выход этого процесса записывает `dead` с `stop_evidence=observed_exit`. После рестарта потерянная связь pid, slot и token сигнал не разрешает. Для этой задачи `QueueControl.settle` после истечения lease записывает тот же терминальный переход с `stop_evidence=lease_expired`, очищает `control_op` и снимает uniq. До истечения lease `settle` возвращает `still_owned` и ничего не пишет. Сканер inflight сам этот переход не делает. Ручная правка Redis для выхода из блокировки не требуется.

## Последствия

Терминальная причина cancel/kill наблюдаема в DLQ вместе с `stop_evidence`. Гонка с finish разрешается порядком успешных транзакций. `settle` не доказывает, что процесс уже вышел: если child ещё выполняет handler после lease, последующий requeue может наложить исполнения. Это явный выбор оператора.
