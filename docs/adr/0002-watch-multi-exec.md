# ADR 0002. Транспорт на WATCH / MULTI / EXEC

## Статус

Принято (2026-11-23).

## Контекст

Нужны согласованные переходы задачи и индексов в Redis Cluster. Отдельный recovery-sweeper и TTL ключа уникальности этому противоречат: возраст записи не доказывает, что задачу можно выдать заново или что uniq свободен.

## Решение

Каждая изменяющая операция очереди выполняется на одном соединении циклом `WATCH`, чтение, проверка, `MULTI`, изменения, `EXEC`, проверка каждого ответа. Lua в протокол не входит. Одна очередь занимает один hash slot. Межочередные атомарные операции не предоставляются.

Согласованность перехода обещается при успешном выполнении всех команд `EXEC`, ожидаемых типах ключей и отсутствии постороннего писателя. Частичный `EXEC` обрабатывается по ADR 0005.

Повторная выдача и удаление terminal-записей выполняются тем же worker path с ограниченным batch. Отдельный sweeper-процесс не запускается. Индекс `q:{queue}:done` входит в контракт ключей, потому что retention `done` иначе не находит hash задачи.

## Последствия

Операция, потерявшая ответ `EXEC`, сверяет receipt и постусловия. Слепое повторение записи запрещено. Срок хранения receipt ограничен и задан в `docs/redis-keys.md`.
